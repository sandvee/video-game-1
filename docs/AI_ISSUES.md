# AI_ISSUES — AI 翻车案例与修复记录

> 规则：任何一次 AI 行为异常（格式、脱轨、语气、逻辑矛盾）都记录在这里，作为提示词/过滤器的迭代依据。格式：日期 · 现象 · 根因 · 修复。

---

## 2026-07 · 导演测试 v1：`[事件]` 标记大量解析失败

- **现象**：11 步中 7 步未解析出 `[事件]` 标记，全部走随机兜底；序列看似成链实为结构巧合，结果不可信。
- **根因**：v4 flash 对"`[事件]id`"这类自定义标记格式的服从性差（输出全角括号/直接写 id/整段旁白），属模型通病。
- **修复（v2 协议）**：
  1. 改**编号选择协议**——提示词只列可选事件并编号，AI 只输出一个数字，模型对数字输出的服从率远高于任意标记；
  2. 提示词**只列满足前置条件的事件**，从结构上杜绝"选了不能选的事件"；
  3. 解析失败**重试一次**（追加"只输出数字"提示），再失败才记违规+随机兜底；
  4. 待办：若数字协议仍不稳，可再加"只输出一个数字"的 few-shot 或改为 JSON `{"pick": n, "narr": "..."}`。

## 复用经验

- 与 AI 约定输出格式时，**优先用"编号/数字/JSON"而不是自定义标记**（如 `[选项]`），否则解析层要做得非常宽容。
- 游戏正式版的对话协议（`[选项]`/`[事件]` 标记）在 M3 接入真 AI 时，**应同步评估是否改用编号/JSON**——避免重蹈 v1 覆辙。
