# COLLABORATION — 双人 + 双 DSH 高效协作手册

> 核心原则一句话：**仓库是两人共享的唯一大脑，各自的 DSH 会话只是两只手。**
> 你们的两条 DSH 上下文不同，完全没关系——只要每次会话都从仓库读真相、把结论写回仓库，两条"手"就能在同一个"大脑"上协同。

## 1. 会话启动模板（每次开始，30 秒）

无论谁开 DSH，第一句话先喂这个：

```
先读这些文件再干活：
- docs/CONTEXT.md（项目背景与约定）
- docs/decisions.md（决策记录）
- docs/ROADMAP.md（任务与进度）
- 本次任务相关文件（例：docs/drafts/NPC_DRAFTS.md、docs/AI_PROTOCOL.md）

任务：……
```

**铁律：文档没读之前，不允许 DSH 开始干活。** 这样两条上下文不同的 DSH 永远站在同一份真相上。

## 2. 会话结束交接（2 分钟）

每次会话结束前，让 DSH 做四件事：

1. **改了什么** → Git commit，提交信息写清「做了什么 / 为什么」（如 `feat: 事件脚本 JSON 格式 v1`）
2. **任务进度** → 在 `docs/ROADMAP.md` 勾选对应任务卡
3. **踩了什么坑** → 追加到 `docs/AI_ISSUES.md`（AI 翻车案例库，两人共享）
4. **下一步给谁** → 更新 `docs/HANDOFF.md`（对方下次打开 DSH 先读它，就知道从哪接）

> 提示：DSH 有 handoff 技能，能自动把会话压缩成交接文档——用它生成第 4 步。

## 3. 文件所有权（减少两个人/两个 DSH 抢同一文件）

| 路径 | 主要归属 | 说明 |
|---|---|---|
| `docs/*` | 两人共有 | 决策与协议谁都可能碰，改动走 PR |
| `prompts/*`（提示词模板） | 编程方维护 | **提示词必须放仓库，禁止只存在各自会话里** |
| `data/npcs/*.json` 人物卡 | 文案方主导 | 编程方只审 JSON 格式合规 |
| `data/events/*.json` 事件脚本 | 文案方起草 | 格式以 `docs/AI_PROTOCOL.md` 为准，先定格式再填内容 |
| `src/*.js` 游戏代码 | 编程方 | 文案方需能读懂（不要求会写） |
| `assets/*` 美术 | 美术方 | 素材命名规范写进 CONTEXT.md |

## 4. 同步规则（随缘聊，但留痕）

- **每次 PR 合并 = 一次书面同步**。GitHub 提交记录就是你们的聊天记录。
- 每周至少一次：翻对方近 3 天的 commit/PR，有疑问直接聊。
- **改协议（`docs/AI_PROTOCOL.md`）是大事**：必须双方确认才能改，改完更新 decisions.md（新决策记录）。
- 认领任务前先看 `docs/ROADMAP.md` 和未合并的 PR/分支——避免两条 DSH 做重复工作。

## 5. 常见坑与对策

| 坑 | 对策 |
|---|---|
| 两人 DSH 各改各的提示词，版本漂移 | 提示词只存 `prompts/`，改走 PR，改前看 PR 列表 |
| 各写一版人物卡/事件格式 | 格式以 `AI_PROTOCOL.md` 为唯一标准；先定格式再填内容 |
| 口头约定不落档，两周后忘了 | 决策只认 `decisions.md`，会话里说"就这么定"不算数 |
| 两条 DSH 重复生成同一内容 | 任务卡从 ROADMAP 认领；开 PR 前先看有没有人在做 |
| 一人改了协议另一个人不知道 | 协议改动必须双方确认 + 更新 decisions.md |
| AI 翻车经验不共享，两人踩两次 | 全部记录进 `AI_ISSUES.md` |

## 6. 最小协作闭环（你们的日常）

```
[编程方] 会话开始→读文档→做任务→commit+PR→对方review→合并→勾ROADMAP
[文案方] 会话开始→读文档+HANDOFF.md→写人物卡/事件→commit+PR→对方review→合并→勾ROADMAP
```
任何一方卡壳 >30 分钟 → 把报错原文丢给 DSH → 解决后把坑写进 AI_ISSUES.md。
